# Task workspace

A personal overview of work across projects, connecting tasks to the conversations and code used to carry them out.

## Language

**Project**: An enrolled BB project associated with a main repository and a unique task identifier prefix.

**Task**: A piece of work belonging to a project, shown on the cross-project board and connected to its relevant threads and context.

**Task identifier**: A permanent project-prefixed reference to a task, such as `HOUSE-12`. Renaming the task or changing its repository path does not change this reference.

**Quick capture**: Creating an Inbox task in an enrolled project with a title and optional Markdown description. Other task details can be added afterward.

**Linked thread**: A BB conversation associated with one task at a time, used to research, plan, implement, or review its work. A task may have multiple linked threads, created from its details or linked afterward.
_Avoid_: Separate task chat

**Task memory**: A lean record of confirmed decisions, relevant findings, work and verification results, unresolved questions, and artifact pointers shared across a task's linked threads. Conversation transcripts remain in those threads.

**Task backup**: A saved copy of the task workspace's records and task memory. Linked BB conversations, repositories and referenced file contents are outside that copy.

**Task branch**: The GitButler virtual branch associated with a task before its first repository change, including planning artifacts.

**Repository-editing session**: A period of work that changes a project's repository. Only one such session is active per repository; other threads may continue research and conversation without writing there.

**Wayfinder map**: A planning artifact maintained through the Wayfinder workflow in linked threads. The task workspace may visualize it but does not become its issue tracker.
